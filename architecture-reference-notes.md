# Architecture reference notes

The provided KuppingerCole page describes Identity Fabric as a strategic, service-oriented framework that connects identities, capabilities, services, and technologies across an enterprise. It emphasizes that Identity Fabric is a design paradigm rather than a product or platform.

Key concepts to adapt into original myIAM copy:

- Capabilities describe what IAM must deliver, including authentication, authorization, lifecycle management, governance, analytics, risk, and privileged access.
- Services group capabilities into reusable identity services shared across domains and use cases.
- Tools implement those services, such as IGA, PAM, CIEM, and authentication platforms.
- An integration/API layer connects identity services, applications, partners, and digital ecosystems.
- Legacy connectors and incremental modernization are valid parts of an architecture.
- An IAM reference architecture turns the strategic Identity Fabric concept into an actionable blueprint for domains, layers, capability relationships, and transformation planning.

The reference page's useful visual hierarchy is: definition first, why it matters, a layered architecture visual, capability/service/tool groupings, integration, and operating-model guidance. The new myIAM page should use original wording, branding, and architecture visuals rather than copying the reference site's text or identity.
